# Интеграция YooKassa — подготовительный модуль

В этом каталоге находится серверный модуль для существующего Google Apps Script проекта E-Hookah.

Модуль добавлен отдельно: исходный Apps Script backend не хранится в GitHub, поэтому нельзя безопасно заменить его или переписать существующие `doGet(e)` / `doPost(e)`.

## Текущий статус

- Модуль создаёт redirect-платёж через API YooKassa.
- Сумма рассчитывается на сервере по текущему Google Sheets каталогу; стоимость из браузера не принимается.
- Проверяются ID товара, наличие и количество.
- Повторный запрос с тем же request_id использует сохранённый YooKassa Idempotence-Key.
- Платежи и статусы записываются во вкладку `YK_Payments`.
- Возвращаемый публичный статус защищён случайным status_token.
- Незавершённые платежи можно сверять с YooKassa по таймеру.
- **Разрешён только тестовый режим. Live-платежи заблокированы.**
- **Фискализация чеков не реализована.**
- Фронтенд пока не подключён к созданию платежа. Существующая форма заявок продолжает работать как раньше.

## Требования к каталогу

Вкладка каталога должна содержать столбцы:

- `Название`
- `Цена, <ВАЛЮТА>` — например, `Цена, RUB` или `Цена, BYN`
- `Статус`

ID товаров соответствуют текущему frontend:

- `E-Hookah Air One` → `air-one`
- `E-Hookah Air One Pro` → `air-one-pro`

Модуль читает актуальные цены и статусы непосредственно из Google Sheets. Если товар не найден или его статус не `В наличии`, платёж не создаётся.

### Важная проверка валюты

В текущем frontend цены отображаются с подписью «руб.», а заголовок таблицы — `Цена, BYN`. Это противоречие нужно устранить до тестирования.

Для российского резидента ЮKassa указывает расчёты в RUB. Для компаний-нерезидентов доступны другие варианты валют в зависимости от договора и страны регистрации. Самостоятельно указывать `BYN` в запросе недостаточно — валюта должна быть разрешена для конкретного магазина. См. [условия для нерезидентов](https://yookassa.ru/non-russian-residents).

**Не меняйте цены и валюту автоматически.** Сначала владелец подтверждает страну регистрации бизнеса, расчётный счёт и валюту договора YooKassa.

## Добавление в существующий Apps Script

1. Откройте действующий Apps Script проект, который обслуживает сайт.
2. Создайте файл `yookassa.gs`.
3. Скопируйте в него содержимое этого файла.
4. В начало существующей функции `doPost(e)` добавьте:

   ```javascript
   var paymentPost = ykRoutePost_(e);
   if (paymentPost) return paymentPost;
   ```

5. В начало существующей функции `doGet(e)` добавьте:

   ```javascript
   var paymentGet = ykRouteGet_(e);
   if (paymentGet) return paymentGet;
   ```

6. Не создавайте вторые `doGet` / `doPost` и не удаляйте обработчики каталога и заявок.
7. Сохраните проект. После завершения настройки обновите существующее Web App deployment новой версией.

Диспетчеризация обрабатывает только запросы с `action=create_yookassa_payment` и `action=yookassa_payment_status`. Все остальные запросы должны продолжить обрабатываться старым кодом.

## Script Properties

Откройте **Project Settings → Script Properties** в Google Apps Script.

| Ключ | Значение |
|---|---|
| `YK_PAYMENTS_ENABLED` | Оставить `false`; для тестового прогона переключить в `true` только после настройки тестовых данных |
| `YK_MODE` | Строго `test`; любое другое значение блокируется |
| `YK_SHOP_ID` | Тестовый Shop ID из кабинета YooKassa |
| `YK_SECRET_KEY` | Тестовый Secret Key из кабинета YooKassa |
| `YK_CURRENCY` | Код валюты договора, совпадающий с заголовком цены в Google Sheets |
| `YK_RETURN_URL` | Полный HTTPS URL сайта для возврата после оплаты |
| `YK_CATALOG_SPREADSHEET_ID` | ID Google Spreadsheet с каталогом |
| `YK_CATALOG_SHEET_NAME` | Точное название вкладки каталога |
| `YK_PAYMENTS_SHEET_NAME` | Необязательно; по умолчанию `YK_Payments` |

Не храните Shop ID/Secret Key в HTML, `script.js`, GitHub или параметрах URL. Не передавайте секретный ключ в чат.

Вкладка `YK_Payments` создаётся автоматически в той же Google Таблице. В ней будут персональные данные заявителя; доступ к самой таблице должен быть только у владельца и сотрудников, которым эти сведения необходимы. Публикуйте в интернете только лист каталога, а не весь документ.

## Периодическая сверка статуса

Прямой YooKassa webhook в Apps Script не добавлен. Google Apps Script `ContentService` отдаёт результат через отдельный Google URL, тогда как webhook-получателю необходимо надёжно подтвердить HTTP 200. Поэтому модуль сверяет платежи через authenticated API `GET /v3/payments/{payment_id}`.

После того как тестовые Script Properties добавлены и тестовое создание платежа разрешено:

1. В редакторе Apps Script выберите `ykInstallPaymentReconciliationTrigger_`.
2. Нажмите **Run** и выдайте разрешения.
3. Создастся один триггер с периодом 5 минут.
4. При необходимости триггер можно удалить функцией `ykRemovePaymentReconciliationTrigger_`.

Каждый запуск проверяет не более 20 незавершённых платежей и сопоставляет payment ID, order ID, сумму, валюту и признак тестового платежа.

## Контракт для будущего frontend

POST на текущий Apps Script endpoint, Content-Type `text/plain;charset=utf-8`:

```json
{
  "action": "create_yookassa_payment",
  "request_id": "уникальный-id-запроса",
  "items": [
    { "id": "air-one", "quantity": 1 }
  ],
  "name": "Имя покупателя",
  "phone": "+79990000000",
  "address": "Адрес",
  "comment": "Комментарий"
}
```

Успешный ответ содержит:

- `payment.confirmation_url` — адрес страницы оплаты;
- `payment.order_id` — идентификатор внутреннего заказа;
- `payment.status_token` — секрет для проверки статуса;
- `payment.status` — текущий статус.

Frontend должен перенаправить пользователя на `confirmation_url`. Нельзя считать платёж успешным по факту возврата пользователя на сайт.

После возврата на `YK_RETURN_URL` будут доступны `order_id` и `payment_status_token`. Статус можно запросить через JSONP на Apps Script endpoint:

- `action=yookassa_payment_status`
- `order_id=<order_id>`
- `status_token=<payment_status_token>`
- `callback=<имя функции>`

Endpoint возвращает только статус, сумму и валюту; ФИО, телефон и адрес не раскрываются.

## Что остаётся до завершения интеграции

1. Владелец предоставляет тестовые Shop ID и Secret Key.
2. Уточняются страна регистрации бизнеса, расчётный счёт и разрешённая валюта ЮKassa.
3. Исправляется расхождение `BYN` / «руб.» в каталоге и интерфейсе.
4. Владелец подтверждает допустимость приёма платежей за конкретные модели E-Hookah и условия ЮKassa для этой категории.
5. Выясняется наличие онлайн-кассы (ККТ), договора с ОФД либо возможность использовать «Чеки от ЮKassa».
6. Для чека уточняются система налогообложения, ставка НДС/признак без НДС, предмет и способ расчёта, а также контакт покупателя. Текущая форма не собирает email.
7. Реализуется frontend-переход к оплате и отдельный экран результата.
8. Перед production выполняются тесты и проверка фискализации. Live mode в этом модуле намеренно не поддерживается.

До выполнения этих условий сайт сохраняет текущую механику отправки заявок.
